Upstream Sources, Tests, Package.swift and MIT license are vendored locally
so the Xcode workspace uses this authentication implementation.

macOS:
CommerceKit CKSigningSession signs the exact serialized login plist.
The Objective-C bridge uses ARC, explicit NSError bridging, and a 30-second
session-opening timeout. Reference: ipatool-sapfix 2.3.2-sapfix.2; adapted
code is covered by LICENSE.ipatool.

Ordinary iOS app builds:
AppleSAPRuntime runs a pinned Go SAP engine and Unicorn WebAssembly runtime
inside a non-persistent WKWebView. Login plaintext remains local. Native
URLSession sends only SAP certificate/setup traffic to the two fixed Apple
endpoints. The bundled page has no remote scripts or arbitrary transport.
A SAP session is reused within one authentication flow. Every request,
redirect and retry signs its exact final XML bytes. Account rotation uses
the same implementation. No unsigned request is sent if signing fails.

Assets are fetched at build time by Resources/Scripts/prepare.sap.runtime.py
from dompling/Jsbox-Ipa commit 620649f818926a6c313c2cf3d4555ae4c318ffa1.
SHA-256 checks pin all three artifacts. They are bundled into the IPA;
no runtime download or signing server is necessary. Source provenance is
an upstream binary artifact; this repository does not reproduce sap.wasm
from its original Go source.

Authentication also normalizes the Apple MZFinance endpoint trailing slash,
uses attempts 1 and 2, removes whitespace from the six-digit 2FA code,
and rejects credential redirects outside Apple authentication endpoints.
Cookies, tokens and SAP signatures are redacted from diagnostic headers.

Build:
python3 Resources/Scripts/prepare.sap.runtime.py --public-certificates
./Resources/Scripts/compile.release.mobile.ci.sh "$PWD" "$PWD/Asspp-SAP.ipa"
Use Asspp.xcworkspace with Xcode 26.2 or newer. The CI packaging script no
longer deletes local patches or prepared resources. CI produces an unsigned
IPA for signing with the user's normal sideloading tool.

Private build source snapshots exclude all certificate/PEM files. The
--public-certificates option restores ONLY upstream's publicly distributed
localhost OTA test certificate/key/CA with immutable hashes, on the build
machine. It does not upload user signing certificates or Apple credentials.

The SAP iOS IPA workflow compiles and tests the WebView first, then builds
and verifies the IPA and uploads it as a private Actions artifact.
